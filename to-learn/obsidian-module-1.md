## Зачем этот модуль

Obsidian по умолчанию настроен под личный блокнот с нуля, а здесь он
надстраивается над готовым git-репозиторием со своими правилами. Пока
настройки не приведены в порядок, всё остальное будет ломать
совместимость с GitHub и с Claude Code. Это не «настройки под вкус», а
условие работоспособности.

## Занятие 1. Настройка vault под этот репозиторий

**Теория (15 мин):** [obsidian.md/help](https://obsidian.md/help/),
раздел Get started, страницы про vault и настройки. Русскоязычные курсы
для этого не нужны, это настройки, а не концепция.

**Практика (45 мин).** Четыре решения, каждое обязательно:

**1. Ссылки: markdown, а не wikilinks.** По умолчанию Obsidian ставит
`[[wikilinks]]`. Весь репозиторий и всё, что пишет Claude Code, на
обычных markdown-ссылках `[текст](путь)`, и GitHub рендерит только их.
Wikilinks на GitHub и в облачной рутине, которая шлёт эти письма,
останутся сырым текстом.
Сделать: `Настройки → Файлы и ссылки → Использовать [[Wikilinks]]: выкл`,
`Тип ссылки: относительный путь к файлу`. Читать существующие wikilinks
Obsidian всё равно умеет.

**2. Папка для новых и для ежедневных заметок.** Сейчас не настроена,
поэтому пустой `2026-08-09.md` лёг в корень и попал в git.
Сделать: создать папку `journal/`, указать её в настройках daily-notes,
задать папку по умолчанию для новых заметок. Удалить `2026-08-09.md` из
корня и из git. Решить, попадает ли `journal/` в git или в `.gitignore`:
личный рабочий журнал в репозитории, который лежит на GitHub, это
осознанное решение, а не мелочь.

**3. Папка для вложений.** По умолчанию вставленная картинка падает в
корень репозитория.
Сделать: задать отдельную папку в `Настройки → Файлы и ссылки → Папка
для новых вложений`.

**4. Горячие клавиши.** Прожать и запомнить: `Ctrl+P` палитра команд,
`Ctrl+O` быстрое переключение файлов, `Ctrl+Shift+F` поиск по vault.

**Проверка:** новая ежедневная заметка создаётся в `journal/`, а не в
корне. Новая ссылка вставляется как `[текст](путь)`, а не `[[текст]]`.

## Занятие 2. Свойства и метаданные

Фундамент под весь модуль 2: и Bases, и Dataview читают именно свойства.

**Теория (20 мин):** документация, раздел про Properties. Типы свойств
(text, list, number, checkbox, date), чем свойства отличаются от
inline-полей Dataview.

**Практика (40 мин):**

   frontmatter показывается в панели свойств
2. Сверить схему из `README.md` (`tier`, `discipline`, `topic`, `type`,
   `status`, `date`) с тем, какие типы Obsidian присвоил полям сам
3. Открыть глобальный поиск по свойству, найти все файлы с
   `status: in-progress`
4. Зафиксировать проблему и не решать её руками: frontmatter стоит в 59
   файлах из 105. Это задача для Claude Code в модуле 4, вручную не
   заполнять

**Проверка:** за 10 секунд находишь в vault все файлы с заданным
значением свойства.

## Занятие 3. Ссылки, обратные ссылки, граф

**Теория (15 мин):** документация, раздел Get started, страница про
связывание заметок. Backlinks, outgoing links, unlinked mentions.

**Практика (45 мин):**

1. Связать `STATE.md` и `DECISIONS_LOG.md` взаимными ссылками
2. Из `STATE.md` поставить ссылки на README текущей дисциплины
   (`tier2/ai-fundamentals/`)
3. Открыть панель backlinks на `DECISIONS_LOG.md`, посмотреть, кто на
   него ссылается
4. Посмотреть unlinked mentions: где файлы упоминаются текстом, но без
   ссылки
5. Открыть Graph view на весь vault и оценить честно: связь читается или
   это красивый шар. Вывод записать одной строкой в раздел «Журнал» ниже

**Проверка:** от `STATE.md` доходишь до любой активной дисциплины за два
клика.
