## Что такое OpenRouter, коротко (проверено 29.08.2026)

Единый API-шлюз и маркетплейс: один ключ и один формат запроса к 500+
моделям от 80+ провайдеров. Базовый адрес `https://openrouter.ai/api/v1`,
совместим с OpenAI SDK как drop-in замена, то есть в коде курса меняются
две строки: `base_url` и ключ.

**Главное, что надо понять сразу и что обычно не пишут в обзорах:
OpenRouter не дешевле прямого доступа к той же модели.** При пополнении
баланса картой берётся 5,5% плюс минимум 0,80 USD за транзакцию.
Платишь за широту выбора, за единый интерфейс, за фолбэки и за
сравнимость, а не за экономию. Экономия появляется только тогда, когда
благодаря сравнению находишь модель дешевле той, что использовал
раньше.

Есть режим BYOK (подключить собственный ключ OpenAI или Google, они уже
есть в `.env` этого репозитория): тогда инференс биллится напрямую
провайдеру, а OpenRouter только маршрутизирует. Условия бесплатного
лимита в BYOK у разных источников расходятся (одни пишут про первый
миллион запросов в месяц, другие про 25 000 USD инференса по прайсу в
месяц), поэтому цифру брать только с официальной страницы тарифов, а не
из обзоров. Проверяется на занятии 1.

Есть примерно 28 постоянно бесплатных моделей и роутер
`openrouter/free`, который сам выбирает бесплатную модель, умеющую
нужные возможности. Годится, чтобы пощупать без денег, но не годится
для замеров: состав и лимиты плавают.

## Конфиденциальность, ключевой пункт для ERC

Это то, из-за чего OpenRouter может оказаться пригодным там, где
NotebookLM был отвергнут (см. собственный разбор
[notebooklm-gemini-obsidian-optimization](../ai-trends/reviews/2026-08-13_notebooklm-gemini-obsidian-optimization.md),
раздел «Зв'язок з ERC»: внешний сервис не подошёл именно по
конфиденциальности внутренних данных).

Что даёт OpenRouter, проверено по официальной документации 29.08.2026:

- логирование промптов **выключено по умолчанию**, по умолчанию хранятся
  только метаданные запроса: число токенов, задержка, модель, время
- параметр `zdr: true` ограничивает маршрутизацию только теми
  эндпоинтами, которые не хранят данные (Zero Data Retention)
- `data_collection: deny` блокирует провайдеров, которые хранят или
  обучаются на входных данных
- хранение и обучение это два **разных** переключателя, есть провайдеры,
  которые не обучаются, но хранят (для антифрода или по закону)
- есть настройки резидентности данных на уровне маршрутизации

Границы, которые надо знать и не переоценивать инструмент:

- ZDR распространяется только на маршрутизацию запросов инференса и
  **не** распространяется на плагины и инструменты вроде веб-поиска
- OpenRouter считает, что кеширование промптов в памяти это не хранение,
  поэтому эндпоинты с неявным кешем остаются доступны при включённом ZDR

Вывод, который проверяется на практике в модуле 4: для замеров и выбора
модели OpenRouter подходит, для боевого прогона внутренних данных ERC
использовать только с явно включённым ZDR и запретом сбора данных, и
только после того, как это сверено с политикой ERC по внешним сервисам.

## Что в плане намеренно нет

**Погони за самой дешёвой моделью.** Дешевизна без замера качества на
своей задаче это не решение, а угадывание. В модуле 1 сравнение идёт по
трём осям сразу: цена, валидность вывода, совпадение с эталоном.

**Разбора всех 500 моделей.** Берутся 3-4 под конкретную задачу.

**Замены прямых API курса.** Код курса и capstone остаётся на прямых
вызовах OpenAI и Google. OpenRouter это инструмент выбора и сравнения,
а не новая обязательная прослойка в проде.
