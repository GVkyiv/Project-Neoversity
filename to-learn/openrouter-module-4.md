# OpenRouter, модуль 4: решение для реальной задачи ERC

Часть плана [openrouter-plan.md](openrouter-plan.md). Неделя
21.09-27.09.2026. Три занятия, примерно 3,5 часа за неделю. Финальный модуль, требует пройденного
[модуля 3](openrouter-module-3.md).

**Статус модуля: в плане**

- [ ] Занятие 10. Выбор задачи и граница по конфиденциальности
- [ ] Занятие 11. Замер на своих данных
- [ ] Занятие 12. Решение, запись в репозиторий, выводы

## Зачем этот модуль

Всё предыдущее делалось на учебной задаче с готовым эталоном. Здесь то
же самое применяется к реальной рабочей проблеме, и результатом должно
быть решение, которое можно защитить цифрами перед коллегами, а не
упражнение.

## Занятие 10. Выбор задачи и граница по конфиденциальности

**Практика (60 мин):**

1. Выбрать одну задачу из [erc-work/context.md](../erc-work/context.md).
   Рекомендуемая: **саммаризация длинных совещаний**, там уже есть
   зафиксированная открытая проблема, `gpt-4o-mini` не справляется на
   длинных записях. Альтернативы: массовое распознавание PDF,
   нормализация кодировки и алфавита в описаниях товаров
2. Сформулировать критерий качества до замера, а не после. Что значит
   «справляется» для саммаризации совещания: полнота решений, отсутствие
   выдуманных участников, длина, наличие ссылок на моменты записи
3. Разобрать границу по конфиденциальности, по разделу
   «Конфиденциальность» в [openrouter-plan.md](openrouter-plan.md):
   логирование промптов выключено по умолчанию, `zdr: true` ограничивает
   маршрутизацию эндпоинтами без хранения данных, `data_collection: deny`
   блокирует провайдеров, которые хранят или обучаются. Хранение и
   обучение это два разных переключателя
4. Зафиксировать ограничения честно: ZDR не распространяется на плагины
   и инструменты вроде веб-поиска, а кеширование промптов в памяти
   OpenRouter хранением не считает
5. **Решить и записать в «Журнал»: можно ли на реальных данных ERC
   вообще, или замер делается на обезличенном фрагменте.** Если есть
   сомнения, сверить с политикой ERC по внешним сервисам, а не решать
   самому

**Проверка:** критерий качества сформулирован письменно до замера, и
решение по данным принято осознанно.

## Занятие 11. Замер на своих данных

**Практика (60 мин):**

1. Подготовить набор: 3-5 фрагментов, где есть эталонный результат,
   то есть где известно, что должно попасть в саммари
2. Выбрать 3-4 модели-кандидата по цене и размеру контекста. Для
   длинных записей размер контекста может оказаться главным критерием,
   а не цена
3. Прогнать с включённым ZDR и запретом сбора данных, промпт одинаковый
   для всех моделей
4. Свести таблицу: модель, размер контекста, стоимость прогона,
   выполнение критерия качества из занятия 10, замеченные провалы
5. Отдельной строкой посчитать: во что обойдётся месячный объём
   совещаний ERC на каждой из моделей

**Проверка:** таблица заполнена, стоимость месячного объёма посчитана
для каждого кандидата.

## Занятие 12. Решение, запись в репозиторий, выводы

**Практика (60 мин):**

1. Сформулировать рекомендацию: какая модель, почему, во сколько
   обойдётся, при каких условиях по данным
2. Написать честный раздел «чего это решение не закрывает». Как минимум:
   зависимость от внешнего сервиса, оговорки по ZDR, что делать при
   отказе провайдера
3. Оформить как задачу в `erc-work/tasks/` по правилам репозитория,
   с frontmatter `tier: erc-work`, `type: task`
4. Если по ходу вылез вывод, который шире этой задачи, записать его в
   [DECISIONS_LOG.md](../DECISIONS_LOG.md)
5. Обновить статус OpenRouter.ai в [backlog.md](backlog.md) на
   `освоено`
6. Сверить с темой 3 текущего курса («Підбір і налаштування LLM»): что
   из пройденного здесь пригодилось для курса, а что курс не покрывает

**Проверка:** есть файл в `erc-work/tasks/` с рекомендацией и цифрами,
который можно показать коллегам, не переписывая.

## Критерий «освоено» по всему плану

1. Понимаешь экономику: когда OpenRouter выгоден, когда переплата
2. Можешь прогнать одну задачу на нескольких моделях кодом и свести
   цифры
3. Умеешь фиксировать провайдера и ставить запасные модели
4. Знаешь, что делать с конфиденциальностью внутренних данных и где
   граница применимости
5. Есть готовая рекомендация по реальной задаче ERC с расчётом
   стоимости
