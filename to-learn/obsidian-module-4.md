## Зачем этот модуль

До сюда был обычный Obsidian, который можно поставить над любым vault.
Этот модуль про то, ради чего он ставится именно над этим
репозиторием: чтобы Obsidian и Claude Code работали по одному
материалу, не мешая друг другу.

## Занятие 11. Разделение труда и git

Принцип, который надо принять и записать: **Claude Code это слой записи,
Obsidian это слой чтения и навигации.** Claude Code создаёт и правит
файлы, соблюдает схему frontmatter, делает коммиты. Obsidian показывает
связи, строит дашборды, даёт быстрый захват. Один файл одновременно в
обоих инструментах не трогать: Obsidian автосохраняет, Claude Code пишет
целиком, кто-то затрёт другого.

**Практика (60 мин):**

1. Установить **Obsidian Git**
2. Настроить: показывать изменения, коммитить вручную. Автокоммит
   выключить, он будет конфликтовать с коммитами Claude Code
3. Закрыть решение по `.obsidian/` в git. Сейчас папка целиком в
   `.gitignore`, значит список плагинов, настройки и представления Bases
   не версионируются и потеряются при переустановке. Варианта два:
   оставить как есть, продублировав список плагинов в
   [obsidian-plan.md](obsidian-plan.md), либо снять игнор с
   `community-plugins.json`, `core-plugins.json` и `app.json`, оставив в
   игноре `workspace.json`, который меняется от каждого клика и будет
   шуметь в git
4. Проверить сценарий: Claude Code меняет файл, в Obsidian изменение
   видно без перезапуска
5. Проверить обратный сценарий: правка в Obsidian видна Claude Code
6. Записать правило разделения труда в `DECISIONS_LOG.md`

**Проверка:** понятно, кто что пишет, оба инструмента видят изменения
друг друга.

## Занятие 12. Правила frontmatter в `AGENTS.md`

Схема frontmatter описана только в `README.md`, а `AGENTS.md`, источник
правды для агентов, о ней не знает. Поэтому 46 файлов из 105 без
frontmatter, и новые файлы Claude Code создаёт без него.

**Практика (60 мин):**

1. Дописать в `AGENTS.md` раздел про обязательный frontmatter со
   ссылкой на схему в `README.md`
2. Поручить Claude Code проставить недостающий frontmatter, не выдумывая
   значения: где дата неизвестна, поле не ставить
3. Проверить результат в базах из модуля 2, они должны наполниться
4. Попросить Claude Code написать новый запрос Dataview под словесную
   задачу, вставить, посмотреть результат. Это и есть рабочий цикл:
   формулировка человеку, синтаксис агенту, просмотр в Obsidian

**Проверка:** файлов без frontmatter не осталось, `HOME.md` показывает
полную картину по репозиторию.

## Занятие 13. Граф, канвас и честная ревизия

**Практика (60 мин):**

1. Graph view с фильтрами: по тегу, по папке, по времени
2. Локальный граф на `DECISIONS_LOG.md`, оценить плотность связей
3. Попробовать Canvas на одной реальной задаче (например схема capstone

4. Ревизия против собственного вывода из
   [разбора 13.08.2026](../ai-trends/reviews/2026-08-13_second-brain-obsidian-zettelkasten-critique.md):

   ради формы. Лишнее отключить
5. Обновить статус Obsidian в [backlog.md](backlog.md) на `освоено`,
   записать итог в `DECISIONS_LOG.md`

**Проверка:** можешь назвать три вещи, которые Obsidian даёт поверх
Claude Code, и две, которые оказались лишними.

## Критерий «освоено» по всему плану

1. `HOME.md` открывается первым и за 30 секунд отвечает, что в работе
2. Статусы ДЗ нигде не ведутся руками, только frontmatter и Bases
3. Новое ДЗ и новый разбор видео создаются одной командой
4. Правило разделения труда с Claude Code записано в `DECISIONS_LOG.md`
5. Можешь объяснить, почему для дашбордов выбран Bases, а не Dataview, и
   где Dataview всё равно нужен
