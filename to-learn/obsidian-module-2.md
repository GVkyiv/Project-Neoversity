## Зачем этот модуль

Ядро всего плана. `README.md` уже заявляет цель: строить автоматические
таблицы статусов вместо ручного ведения в `STATE.md` и `CALENDAR.md`.
Frontmatter под это проставлен, а таблиц нет. Этот модуль их делает.

## Занятие 4. Bases: первая база

Bases это core-плагин, он уже включён, ставить ничего не нужно. В 2026
вышел из беты и стал первопартийным ответом на Dataview. Отличия:
не требует учить язык запросов, ячейки правятся прямо в таблице,
работает быстрее на больших vault.

**Теория (20 мин):** документация по Bases: создание базы, типы
представлений (таблица, карточки, список).

**Практика (40 мин):**

1. Создать файл базы в корне, назвать `Домашние задания`
2. Источник: все файлы, где `type: homework`
3. Колонки: `tier`, `discipline`, `topic`, `status`, `date`
4. Отсортировать по `tier`, затем по `date`

**Проверка:** таблица показывает реальные ДЗ, а не пустоту. Если пусто,
причина в недостающем frontmatter, это ожидаемо и лечится в модуле 4.

## Занятие 5. Bases: представления, фильтры, формулы

**Теория (15 мин):** документация по Bases: фильтры, группировка,
формулы, несколько представлений в одной базе.

**Практика (45 мин):**

1. В базе `Домашние задания` добавить второе представление: карточки,
   сгруппированные по `discipline`
2. Добавить фильтр «только `status: in-progress`»
3. Создать вторую базу `Разборы видео` по `tier: ai-trends`
4. Создать третью базу `Задачи ERC` по `tier: erc-work`
5. Проверить, что файлы баз попадают в git: они лежат в vault, а не в
   `.obsidian/`, значит Claude Code их видит и может править

**Проверка:** три базы работают, переключение представлений даёт разный
срез по одним и тем же файлам.

## Занятие 6. Dataview: язык запросов DQL

Bases закрывает дашборды, но три вещи он не умеет: запросы внутри
предложения, запросы по задачам (чекбоксам) и произвольные вычисления.
Ради них Dataview остаётся, он уже установлен.

**Теория (25 мин):**
[документация Dataview](https://blacksmithgu.github.io/obsidian-dataview/),
разделы Query Types и Data Commands. Формы `TABLE`, `LIST`, `TASK` и
команды `FROM`, `WHERE`, `SORT`, `GROUP BY`.

**Практика (35 мин):**

1. Написать `TABLE status, date FROM "tier2" WHERE type = "homework"`
2. Переписать его же с `SORT date DESC`
3. Написать `TASK`-запрос, собирающий незакрытые чекбоксы из
   `to-learn/backlog.md` и `erc-work/`
4. Сравнить с тем, что даёт Bases, и сформулировать разницу своими
   словами

**Проверка:** пишешь рабочий DQL-запрос, не подглядывая в документацию.

## Занятие 7. Дашборд-нота и сшивка со `STATE.md`

**Теория (10 мин):** inline-запросы Dataview (синтаксис с обратными
кавычками). `dataviewjs` только посмотреть, не углубляться.

**Практика (50 мин):**

1. Создать `HOME.md` в корне: единая точка входа в vault
2. Вставить ссылки на три базы из занятия 5
3. Добавить `TASK`-запрос с открытыми пунктами из `to-learn/backlog.md`
4. Добавить inline-запрос, считающий число файлов со `status: done`
5. Добавить в `HOME.md` блок «Учебные модули Obsidian» со ссылками на
   четыре файла модулей и их статусами
6. Решить и записать: что остаётся в `STATE.md` руками (текущий
   контекст, куда я иду), а что уезжает в автоматический дашборд
   (статусы, счётчики, списки). Решение потом переносится в
   `DECISIONS_LOG.md` в модуле 4

**Проверка:** `HOME.md` открывается первым и отвечает на вопрос «что у
меня сейчас в работе» без чтения других файлов.
