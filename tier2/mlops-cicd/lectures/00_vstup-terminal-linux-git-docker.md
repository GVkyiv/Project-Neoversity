# Операційна база MLOps: Термінал, Linux, Git і Docker

Вступ

Вітаємо на курсі!

Перш ніж ви почнете навчати, пакувати й розгортати моделі в основних дисциплінах, є рівень, який варто опанувати заздалегідь, - той, на якому вся ця робота фізично відбувається.

ML-розробка не живе всередині ноутбука. Код доводиться версіонувати й узгоджувати в команді, середовище - відтворювати, застосунок - пакувати так, щоб він однаково запускався на чужій машині та на сервері. Усі ці операції спираються на чотири технічні навички, і саме їх дає цей курс.

Це не курс самого MLOps. Це його операційна база - термінал, Unix/Linux, Git і Docker. Без неї основні дисципліни доведеться вчити, паралельно доганяючи інструменти; з нею ви заходите туди підготовленими.

Курс є опціональним: він розрахований на тих, хто ще не вивчав ці теми окремо. Якщо ви вже впевнено працюєте в терміналі, з Git і контейнерами - використайте курс як швидке повторення або одразу переходьте до тестування. Якщо ж цей шар для вас новий - пройдіть його послідовно, бо кожна тема спирається на попередню.

Що ви отримаєте

Після курсу ви зможете впевнено працювати в командному рядку, орієнтуватися в Linux-середовищі, версіонувати код через Git і GitHub та пакувати застосунки в Docker-контейнери - тобто оперувати тим самим набором інструментів, який в основних дисциплінах стає щоденним.

План курсу - чотири теми, що йдуть однією ниткою:

Командний рядок (термінал). Прямий і точний спосіб керувати інструментами розробки, більшість із яких працюють через CLI. Це базовий пререквізит для всього решти.

Основи Unix/Linux. Операційна система, на якій реально крутяться сервери, контейнери й обчислювальні кластери, - середовище, куди потрапляють ML-навантаження.

Системи контролю версій Git і GitHub. Версіонування коду та спільна робота - механізм, до якого згодом чіпляються CI/CD-процеси.

Основи технології Docker. Пакування застосунку так, щоб він однаково запускався будь-де. Контейнер - це та одиниця, яку MLOps-пайплайни збирають, переміщують і розгортають.

Теми вибудувані як шари - термінал → Linux → Git → Docker. Кожен наступний спирається на попередній, тож порядок проходження має значення.

Починаємо з терміналу - інструмента, без якого не обійдеться жодна з наступних тем.

Вступ

Термінал - це не інструмент минулого і не атрибут «справжнього програміста». Це спосіб взаємодії з комп'ютером, без якого неможливо повноцінно працювати з більшістю сучасних інструментів розробки: системами контролю версій, контейнерами, базами даних, середовищами розгортання. Багато з них просто не мають графічного інтерфейсу - або він є, але термінал залишається швидшим і точнішим.

Ця тема закриває базовий пререквізит: після неї ви зможете впевнено орієнтуватися в командному рядку і виконувати типові операції з файлами та директоріями. Якщо ви вже маєте цей досвід - використайте тему як швидке повторення або одразу переходьте до тестування.

Після завершення теми ви зможете:

Пояснювати різницю між графічним інтерфейсом (GUI) і командним рядком (CLI) та обирати відповідний інструмент залежно від задачі.

Відкривати термінал на своїй операційній системі та виконувати команди.

Орієнтуватися у файловій системі через термінал: перевіряти поточне розташування, переглядати вміст директорій, переміщатися між ними (pwd, ls, cd).

Створювати, переміщувати, копіювати та видаляти файли і директорії (mkdir, touch, mv, cp, rm).

Читати фідбек термінала, розпізнавати помилки введення та виправляти їх.

Тема складається з двох частин.

Частина 1 - Налаштування і навігація. Розберетесь, що таке CLI і чим він відрізняється від GUI, налаштуєте термінал на своїй ОС і освоїте команди навігації: pwd, ls, cd.

Частина 2 - Керування файлами і директоріями. Навчитесь створювати, видаляти, переміщувати і копіювати файли та директорії: mkdir, touch, rm, mv, cp. Наприкінці - зведений список команд і фінальне тестування.

💡 Кожен блок містить відео-демонстрацію і квіз для закріплення. Команди можна одразу повторювати у власному терміналі - це найефективніший спосіб засвоїти матеріал.

GUI та CLI

Графічний інтерфейс (GUI)

Для взаємодії з комп'ютером більшість користувачів звикли до графічного інтерфейсу - вікна, кнопки, меню, миша. Це і є GUI (Graphical User Interface, графічний інтерфейс користувача). GUI спроєктований так, щоб зробити повсякденну роботу з комп'ютером інтуїтивно зрозумілою: запуск програм, копіювання файлів, налаштування системи - все виконується через клік або перетягування.

Альтернатива GUI - CLI (Command Line Interface, інтерфейс командного рядка). Замість кліків і меню - текстові команди, які вводяться у терміналі. CLI призначений для технічних фахівців і дає значно більше контролю над операціями системи та програмами.

Два поняття, які важливо розрізняти:

Через термінал можна виконувати широкий спектр завдань:

модифікацію системних налаштувань

встановлення програмного забезпечення

керування файлами та папками

усунення несправностей комп'ютера

Фактично майже всі дії, доступні через GUI, можна виконати і через термінал - часто швидше й точніше.

Переваги CLI

Робота в текстовому інтерфейсі може здатися менш зручною порівняно з GUI - особливо спочатку. Проте з часом стає помітно, що CLI економить значний ресурс: рутинні дії, які в GUI займають кілька кліків через вкладені меню, у терміналі виконуються однією командою.

Фахівці використовують CLI з кількох причин:

Загалом термінал дає більше контролю, швидкість виконання та можливість автоматизації - і є невід'ємною частиною робочого процесу більшості IT-фахівців.

💡 На практиці: на співбесіді чи в робочому середовищі відсутність базових навичок роботи з терміналом - це помітний недолік. Саме тому варто починати нарощувати «м'яз» командного рядка якомога раніше: розуміння і комфорт приходять через практику.

Більшість інструментів, з якими ви працюватимете далі - системи контролю версій, засоби розгортання, інструменти роботи з даними - взаємодіють саме через CLI або вимагають базового розуміння термінала. Ця тема закладає фундамент для всього, що буде далі.

Встановлення Git Bash на Windows

Якщо ви використовуєте macOS або Linux - пропустіть цей розділ і переходьте до наступного.

Вбудований термінал Windows не підтримує низку команд Unix-систем, які використовуються в більшості інструментів розробки. Щоб працювати з тими самими командами, що й на macOS та Linux, потрібно встановити Git Bash - термінал, який відтворює Unix-середовище на Windows.

Вихід із термінала

Будь-яка взаємодія з терміналом відбувається однаково: ви вводите команду з клавіатури та натискаєте Enter. Термінал виконує команду і у більшості випадків виводить результат на наступному рядку.

Щоб виконати команду, введіть її в терміналі та натисніть Enter.

Цей результат називають фідбеком термінала. Він повідомляє, чи була команда виконана успішно і що саме відбулося. Якщо ви допустили помилку в назві команди, термінал відповість повідомленням "Command not found" - команда не знайдена. Уважно читайте фідбек після кожної команди: у разі помилки там буде пояснення того, що пішло не так.

Вводьте команди уважно: термінал сприймає текст буквально і не виправляє помилки автоматично.

Команда exit

Перша команда, яку ми розглянемо, - exit. Вона завершує сеанс термінала і працює однаково на будь-якій операційній системі.

Введіть exit у командний рядок.

Натисніть Enter.

Для практики відкрийте та закрийте термінал кілька разів.

quit

Саме так! Введення цієї команди в командний рядок закриє термінал.

Поточне розташування

pwd розшифровується як print working directory - вивести поточну робочу директорію. Результатом буде шлях до папки, в якій ви зараз знаходитесь у файловій системі.

Перегляд вмісту папки

У графічному інтерфейсі вміст папки видно одразу - у вигляді іконок або списку. У терміналі для цього є команда ls (від list directory): вона виводить перелік файлів і папок у поточній робочій директорії.

Введіть ls і натисніть Enter.

Прапорці: розширений вивід

Більшість команд у терміналі підтримують прапорці - додаткові опції, що змінюють поведінку команди. Прапорець вказується після команди через пробіл і починається з дефіса.

ls -l виводить детальний список файлів у поточній директорії з додатковою інформацією: розмір, дата та час останньої модифікації.

⚠️ Між ls і -l обов'язково має бути пробіл - інакше термінал не розпізнає прапорець.

ls -a показує всі файли у директорії, включно з прихованими (їх назви починаються з крапки, наприклад .gitconfig).

Прапорці можна комбінувати: ls -la одночасно виведе детальний список і покаже приховані файли.

Яка команда виведе вміст поточної папки у вигляді списку з додатковою інформацією про розмір, дату тощо?

ls

ls -l

ls -a

Результат

Правильно! Команда ls -l виведе детальний список файлів у поточній директорії з додатковою інформацією про розмір, дату тощо.

Переміщення у файловій структурі

Команда cd

У графічному інтерфейсі для переміщення між папками використовується миша - подвійний клік відкриває папку, стрілка «назад» повертає на рівень вище. У терміналі для цього є команда cd (від change directory - змінити директорію).

cd [ім'я директорії]

Команда складається з двох частин:

cd - команда, яку термінал розпізнає як інструкцію змінити директорію

[ім'я директорії] - назва директорії, в яку потрібно перейти

⚠️ Квадратні дужки позначають місце для вашого значення - у саму команду їх не включають.

Відносний шлях

Перш ніж перейти до прикладів, важливо розуміти, як термінал інтерпретує назву директорії у команді cd.

Коли ви вводите cd Desktop - термінал шукає папку Desktop відносно вашої поточної директорії. Такий запис називається відносним шляхом: він описує маршрут від того місця, де ви зараз знаходитесь, а не від кореня файлової системи.

Наприклад, якщо ви знаходитесь у домашній директорії і хочете переглянути вміст папки Desktop - спочатку перейдіть у неї командою cd, а потім виконайте ls:

cd Desktop

ls

Два напрямки навігації

У файловій структурі можна переміщатися у двох напрямках:

вперед - у вкладену директорію: cd [ім'я директорії]

назад - на один рівень вгору, до батьківської директорії: cd ..

Виконайте це кілька разів для практики: поверніться в домашню директорію, потім перейдіть у Desktop і назад.

Якщо загубились у файловій структурі

Якщо ви не впевнені, де зараз знаходитесь і як повернутися - є два кроки:

Введіть pwd, щоб побачити поточну директорію та зрозуміти своє розташування.

Введіть cd ~, щоб повернутися в домашню директорію користувача. Звідти можна починати навігацію заново.

💡 Символ ~ (тильда) - скорочення для домашньої директорії вашого користувача. На стандартній клавіатурі тильда зазвичай розташована під клавішею Esc.

Створення директорії

Команда mkdir

Створення директорій - типова задача при роботі з проєктами. Команда mkdir (від make directory - створити директорію) створює нову папку в поточній директорії, де ви зараз знаходитесь у терміналі.

mkdir [ім'я директорії]

⚠️ Квадратні дужки позначають місце для вашого значення - у саму команду їх не включають.

Для прикладу створімо у домашній директорії папку Projects - у ній зручно зберігати робочі проєкти.

Як перевірити, що директорію створено

Після виконання mkdir термінал не виводить підтвердження - просто повертає новий рядок. Щоб переконатися, що папка з'явилась, виконайте ls і перевірте, чи вона є у списку.

⚠️ Успішне створення папки не означає, що ви знаходитесь всередині неї. Щоб перейти у щойно створену директорію, виконайте cd [ім'я директорії].

Будь-яка зміна, внесена через термінал, відображається у графічному провіднику (Finder / Windows Explorer) і навпаки - обидва інструменти працюють з однією й тією самою файловою системою.

Для практики створіть папку my-project всередині папки Projects і перейдіть у неї.

Створення кількох папок одночасно

mkdir може створити кілька директорій за одну команду - перерахуйте їх назви через пробіл:

mkdir папка1 папка2 папка3

Створення файлів

Команда touch

Для створення порожнього файлу в терміналі використовується команда touch:

touch [ім'я файлу]

Для користувачів Windows у PowerShell аналогічна команда - New-Item:

New-Item [ім'я файлу]

Наприклад, touch example.txt створить порожній файл з ім'ям example.txt у поточній робочій директорії.

💡 Якщо файл з такою назвою вже існує, touch оновить час останнього доступу до нього, але не змінить вміст.

Створення кількох файлів одночасно

Як і mkdir, команда touch може створити кілька файлів за одну команду - перерахуйте їх назви через пробіл:

touch файл1.txt файл2.txt файл3.txt

Створення файлу у вкладеній директорії

Файл можна створити не лише в поточній директорії, а й у вкладеній - для цього вкажіть відносний шлях від вашої поточної директорії.

Наприклад, якщо ви знаходитесь у папці my-project і хочете створити файл todo.txt у вкладеній папці first:

touch first/todo.txt

Термінал інтерпретує first/todo.txt як: «файл todo.txt у підпапці first відносно поточної директорії».

Видалення файлів і директорій

Для видалення об'єктів у терміналі є кілька команд - вибір залежить від того, що саме потрібно видалити.

Команда rmdir - видалення порожньої директорії

rmdir (від remove directory) видаляє порожню директорію:

rmdir [ім'я директорії]

💡 Користувачі Windows, які працюють у Git Bash, виконують ті самі команди, що й на macOS та Linux: rmdir, rm, rm -rf.

Команди видалення підтримують відносні шляхи. Наприклад, щоб видалити порожню папку third, вкладену в my-project, потрібно знаходитись у my-project і виконати:

rmdir third

Команда rm -rf - видалення непорожньої директорії

rmdir не видаляє директорії, що містять файли. Якщо спробувати виконати rmdir для непорожньої папки, термінал поверне помилку:

Directory not empty

Для видалення директорій з вмістом використовується команда rm з прапорцями:

rm -rf [ім'я директорії]

Де:

rm - команда для видалення файлів або директорій

-r - рекурсивне видалення: видаляє директорію разом із усіма вкладеними файлами та піддиректоріями

-f - примусове видалення без запиту підтвердження

⚠️ rm -rf видаляє дані без можливості відновлення - кошик не використовується. Перед виконанням переконайтесь, що вказали правильний шлях.

Видалення кількох об'єктів одночасно

Будь-яка команда видалення може обробляти кілька об'єктів за один виклик - перерахуйте їх через пробіл:

rm файл1.txt файл2.txt

rm -rf папка1 папка2

Команда rm з підтвердженням

Якщо виконати rm без прапорців для видалення файлу, термінал запитає підтвердження для кожного об'єкта. Введіть y (yes) або n (no) і натисніть Enter.

Щоб пропустити підтвердження, використовуйте прапорець -f:

rm -f [ім'я файлу]

Переміщення та перейменування файлів

Команда mv

Команда mv (від move - перемістити) переміщує файл або директорію в нове місце. Також mv використовується для перейменування.

mv [джерело] [призначення]

Де:

[джерело] - файл або директорія, яку потрібно перемістити

[призначення] - нове місце або нова назва

Перейменування файлу

Якщо джерело і призначення знаходяться в одній директорії, mv перейменовує файл.

Наприклад, перейменуємо file1.txt на todo.txt, знаходячись у папці my-project:

mv file1.txt todo.txt

Переміщення файлу у вкладену директорію

Щоб перемістити файл у вкладену папку, вкажіть її назву як призначення.

Наприклад, переміщуємо todo.txt у вкладену папку stash, знаходячись у my-project:

mv todo.txt stash

Переміщення файлу на рівень вгору

Так само, як cd .. переходить на рівень вгору в навігації, mv з .. як призначенням переміщує файл у батьківську директорію.

Наприклад, повернемо todo.txt з папки stash назад у my-project. Для цього знаходимось у stash і виконуємо:

mv todo.txt ..

Копіювання файлів і директорій

Команда cp

Команда cp (від copy - копіювати) створює копію файлу або директорії в новому місці. На відміну від mv, вихідний файл або директорія залишаються незмінними.

cp [джерело] [призначення]

Де:

[джерело] - файл або директорія, яку потрібно скопіювати

[призначення] - місце, куди потрібно скопіювати

💡 Якщо ви копіюєте непорожню директорію, разом з нею копіюється весь її вміст.

Наприклад, створимо копію файлу file2.txt у папці stash, знаходячись у my-project:

cp file2.txt stash

Очищення екрана термінала

Команда clear

Команда clear очищає екран термінала - всі попередні виведені дані зникають, і ви отримуєте чисте робоче поле.

Альтернатива - комбінація клавіш, яка робить те саме без введення команди:

Ctrl + L - для Windows та Linux

Control + L - для macOS

Довідка

Команда man

Для пошуку інформації про команди термінала є два основні варіанти: інтернет і вбудована документація.

Команда man (від manual - посібник) відкриває вбудовану документацію для будь-якої команди:

man [команда]

Наприклад, щоб переглянути документацію для mv:

man mv

Прокручування тексту - клавішами вгору/вниз або колесом миші. Щоб закрити документацію і повернутися до термінала, натисніть q.

💡 Документація man доступна лише англійською мовою.

Альтернатива для Git Bash на Windows

У Git Bash команда man може бути недоступна залежно від версії. Універсальна альтернатива - прапорець --help, який підтримується більшістю команд:

mv --help

ls --help

Вивід буде коротшим, ніж у man, але містить основну інформацію про синтаксис і прапорці.

Підсумки

У цій темі ви ознайомились із базовими інструментами роботи в командному рядку - від навігації у файловій системі до керування файлами та директоріями. Нижче наведено зведений список команд для довідки.

Про тестування:

Після відповіді на всі питання ви отримаєте розгорнутий фідбек.

На проходження тестування відведено 15 хвилин та 2 спроби. Поставити час на паузу неможливо.

Відповідь неправильна

Ви знаходитесь у директорії my-project. У ній є підпапка data, а в ній - підпапка raw. Яка команда переведе вас у raw за один крок? my-project/ └── data/ └── raw/

cd raw

cd data raw

cd data/raw

cd ../raw

Результат

Так, правильно. Відносний шлях data/raw описує маршрут від поточної директорії вниз по структурі. Саме тому можна перейти одразу на два рівні вниз без проміжних кроків.

Ви у папці images. Потрібно перейменувати файл photo.jpg у підпапці 2023 на avatar.jpg. Яка команда це зробить? images/ ├── 2022/ └── 2023/ └── photo.jpg

mv photo.jpg avatar.jpg

mv 2023/photo.jpg avatar.jpg

mv 2023/photo.jpg 2023/avatar.jpg

cp 2023/photo.jpg 2023/avatar.jpg

Результат

Цей варіант виглядає логічно, але призведе до неочікуваного результату. Якщо не вказати шлях у другому аргументі - файл переміститься в поточну папку images. А cp залишить оригінал, не перейменовуючи його. У цій ситуації пріоритет - вказати однакову директорію в обох аргументах. Повернись до блоку про команду mv, щоб закріпити цей момент.

Ви у папці project. Потрібно видалити папку cache, яка містить тимчасові файли. Яка команда підходить? project/ ├── src/ ├── cache/ │ ├── tmp1.log │ └── tmp2.log └── README.md

rmdir cache

rm cache

rm -rf cache

rm -f cache

Результат

Так, правильно. cache непорожня, тому звичайний rmdir не спрацює. Прапорець -r видаляє директорію разом із вмістом рекурсивно, -f прибирає запит підтвердження. Саме тому rm -rf - стандартний спосіб видалення непорожніх директорій. ⚠️ Дані видаляються без можливості відновлення.

Ви у папці reports. Потрібно скопіювати файл q1.pdf з підпапки 2023 у підпапку 2024. Яка команда це зробить? reports/ ├── 2023/ │ └── q1.pdf └── 2024/

cp q1.pdf 2024/

cp 2023/q1.pdf 2024/

mv 2023/q1.pdf 2024/

cp 2023/q1.pdf 2023/2024/

Результат

Цей варіант виглядає логічно, але призведе до помилки або втрати даних. cp q1.pdf 2024/ шукає файл у поточній папці - де його немає. mv перемістить файл, а не скопіює - оригінал зникне. 2023/2024/ - неіснуючий шлях. У цій ситуації пріоритет - правильно вказати відносний шлях до джерела. Повернись до блоку про команду cp, щоб закріпити цей момент.

Ви у папці workspace/project/src. Яку послідовність команд виконати, щоб повернутись у workspace і переглянути її вміст?

cd ~ → ls

cd .. → cd .. → ls

pwd → ls

cd workspace → ls

Результат

Так, правильно. Кожен cd .. піднімає на один рівень вгору: перший - з src у project, другий - з project у workspace. Потім ls показує вміст. Саме тому для переміщення на кілька рівнів вгору команду cd .. повторюють потрібну кількість разів.

Потрібно у поточній директорії backend створити папку logs, потім перейти в неї і створити порожній файл app.log. Яка послідовність команд правильна?

touch logs/app.log → mkdir logs → cd logs

mkdir logs → touch logs/app.log

mkdir logs → cd logs → touch app.log

cd logs → mkdir logs → touch app.log

Результат

Цей варіант виглядає логічно, але призведе до помилки. A намагається створити файл у logs до того, як папка існує - термінал поверне помилку. D намагається перейти в logs до його створення - та сама проблема. У цій ситуації пріоритет - спочатку створити директорію, потім працювати всередині неї. Повернись до блоків про команди mkdir, touch і cd, щоб закріпити цей момент.
