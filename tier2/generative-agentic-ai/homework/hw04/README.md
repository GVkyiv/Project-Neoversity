# ДЗ4. LLM для базового аналізу та генерації масивів текстів

Умова: [hw04_task.md](hw04_task.md). Файл на здачу:
[hennadii_volenbovskyi.ipynb](hennadii_volenbovskyi.ipynb), виконаний, з
збереженими виводами комірок.

## Що всередині

Три завдання в трьох окремих комірках плюс четверта комірка з перевіркою
стабільності:

1. Персона плюс тональність щодо неї.
2. Тріаж відгуків: продукт плюс пріоритет.
3. Заголовок до 8 слів плюс категорія оголошення.

## Модель і вартість

`gpt-4.1-nano` через прямий OpenAI API (ключ з `.env` репозиторію, у ноутбук
не потрапляє). Ноутбук перемикається на OpenRouter автоматично, якщо в
середовищі є `OPENROUTER_API_KEY`. Повний прогон, 60 викликів разом з
перевіркою стабільності, коштує приблизно 0.001 USD при бюджеті до 1 USD за
умовою.

## Результат прогону 28.08.2026

- 45 контрольних викликів (15 текстів по 3 повтори), 45 валідних JSON з
  правильним складом ключів і значеннями лише з дозволених множин.
- 45 збігів з еталоном умови в полях, що оцінюються.
- Розкид відповідей на однаковому вході: 1 текст із 15, і лише в полі
  `title` (генеративне поле, умова допускає різні заголовки). Усі
  класифікаційні поля відтворюються один в один.

## Прийоми промптингу, які спрацювали

Однакова конструкція в усіх трьох промптах: вузька роль замість універсального
асистента, жорсткий контракт формату з фіксованим порядком ключів, закриті
множини значень, три few-shot приклади на сторонніх текстах (не з датасету,
щоб не було підгонки), один negative example з кількома типовими збоями
одразу, прихований chain-of-thought, окремі правила для розв'язання
конфліктів між сигналами.

Два спірні кейси з умови закриті узагальненим правилом, а не прикладом:
наявність ручного обходу не знижує пріоритет, і будь-яка недоступність
сервісу, включно з плановою, це інцидент.
