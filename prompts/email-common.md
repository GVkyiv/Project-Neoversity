# Спільне для листів-нагадувань по навчанню

Правила, однакові для всіх листів з родини «навчання»: [email-weekly.md](email-weekly.md)
(понеділок), [email-friday-reminder.md](email-friday-reminder.md) (п'ятниця),
[email-monthly-overview.md](email-monthly-overview.md) (1 число місяця).
Кожен лист це окрема хмарна рутина зі своїм розкладом, цей файл вони
підключають як спільну базу, щоб правила форматування не розходились
між ними.

Виділено 14.09.2026 з одного файлу `weekly-study-email.md`: три листи
розрослись в одну інструкцію, стало важко правити один лист, не
чіпаючи інші. Тепер кожен лист це окрема сутність зі своїм файлом.

## Звідки рутина читає дані

Рутина читає файли з **GitHub** (`GVkyiv/Project-Neoversity`, гілка
`master`), а не з локального диска. Якщо статус оновлено локально і не
запушено, лист покаже старі дані. Це джерело помилки, яка вже траплялась:
наприклад, статус модуля позначено `done` локально, лист все одно
показує його незакритим, бо коміт не потрапив у `master`.

Усі три листи це хмарні рутини, керуються через скіл `schedule` або на
сторінці https://claude.ai/code/routines. Час у cron задається в UTC,
тому 10:00 Києва влітку це `0 7`.

## Як оформляти посилання

**Відсутність слів-обгорток.** Слів «Відкрити», «Дивитись», «Пройти
курс», «Посилання» не має бути, як і самих посилань на GitHub.
Посилання вішається прямо на назву того, що відкривають, через
`<a href>`.

Що стає посиланням:

| Текст у листі | Куди веде |
|---|---|
| Назва модуля («Obsidian, модуль 1: база і гігієна vault») | файл модуля в Obsidian |
| Кожна назва заняття («Заняття 1. Налаштування vault...») | той самий файл, з переходом до заголовка цього заняття |
| Назва курсу Anthropic Academy | сторінка курсу, адреса з таблиці `backlog.md` як є |

**Як зібрати посилання на файл модуля.** Vault: `AI Project` (корінь
піднятий на два рівні вище, репозиторій лежить всередині як
`Study/Project Neoversity`):

```
obsidian://open?vault=AI%20Project&file=Study%2FProject%20Neoversity%2Fto-learn%2F<ім'я-файлу-без-розширення>
```

Готові посилання цього вигляду вже лежать у `obsidian-plan.md` і
`openrouter-plan.md`, копіювати звідти дослівно.

**Як зібрати посилання на конкретне заняття.** До тієї самої посилки
дописати `%23` і URL-кодований заголовок заняття з тіла файлу модуля
(у файлі це рядок вигляду `## Заняття 1. Назва`, брати її цілком без
решіток). Кодувати через python, не вручну:

```python
import urllib.parse
anchor = urllib.parse.quote("Заняття 1. Назва", safe="")
```

Результат приклеюється до посилання на файл:
`obsidian://open?vault=AI%20Project&file=Study%2FProject%20Neoversity%2Fto-learn%2F<файл>%23<anchor>`

Якщо заголовок закодувати не вдалось, ставити звичайне посилання на
файл модуля без якоря. Биту посилку не відправляти ніколи.

## Типографіка листа

`htmlBody` цілком обгорнути в контейнер з базовим розміром шрифту
**17px** і `line-height: 1.5`. Це приблизно на 20% крупніше того, що
поштовий клієнт ставить за замовчуванням: лист читається з телефону.
Заголовки блоків 21-22px, назви треків 19px. Посилання підкреслені,
щоб було видно, що це посилання.

Приклад каркасу:

```html
<div style="font-size:17px; line-height:1.5; font-family:-apple-system,Segoe UI,Roboto,sans-serif;">
  ...
</div>
```

У полі `body` (простий текст) розмір шрифту задати не можна, туди йде
той самий текст без розмітки, а посилання виписуються повними
адресами в дужках після назви.

## Правила тексту

- Мова листа російська
- Тире не використовувати, замість нього дефіс, кома або двокрапка
  (загальне правило репозиторію з `AGENTS.md`)
- Нічого не вигадувати: чого немає у файлах, того немає в листі
- Джерело правди по статусу модуля це `status` у frontmatter файла
  модуля, статуси в `backlog.md` не дублюються і не перевіряються
  повторно
