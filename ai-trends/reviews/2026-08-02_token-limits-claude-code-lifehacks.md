# Как никогда не упираться в лимиты: Claude і Codex

## Джерело

YouTube, "(586) Как НИКОГДА не упираться в лимиты | Claude и Codex"
(https://www.youtube.com/watch?v=J04REnA4VFQ). Дата перегляду: 2026-08-02.

## Резюме

Розбір лайфхаків для економії токенів і лімітів у Claude Code/Codex/Cursor.
Технічна база: агент на кожне нове повідомлення заново прогонює всю
історію чату, тому довгі чати дорогі й деградують ("context rot").
Практичні поради: не плодити сміттєві виправлення (краще відкат/
редагування повідомлення, ніж лаяти модель), `/btw` для побічних питань
без навантаження на історію, короткі відповіді (вихідні токени дорожчі за
вхідні), не перевищувати ~120k токенів в чаті і відкривати новий чат під
кожну велику задачу, субагенти і скіли (підвантажуються лише коли треба),
`CLAUDE.md`/`AGENTS.md` до 200 рядків з посиланнями на окремі md-файли,
вимикати непотрібні MCP, вибирати модель по складності задачі, Plan Mode
перед великими задачами, конвертація PDF/Word в markdown. Окремий блок про
5-годинне вікно лімітів Claude Code через Routines і партнерство Anthropic
зі SpaceX (доступ до дата-центру Colossus в Мемфісі, подвоєння лімітів
6 травня 2026).

## Факт-чек

- **Токени/слова** (1 токен ≈ ¾ англійського слова, 1 російське слово ≈
  2-3 токени) - підтверджено, відповідає загальноприйнятим оцінкам
  токенізаторів.
- **Вхід дешевший за вихід у 5 разів** - підтверджено точно: ціна Sonnet 5
  на серпень 2026 - $2/$10 (або $3/$15 після 31.08) за млн токенів,
  співвідношення рівно 5x.
- **"Модель щоразу перечитує всю історію з нуля, це дорого"** - вірно в
  принципі, але важливе упущення: у Claude Code є prompt caching -
  повторюваний префікс розмови кешується, повторне читання коштує ~10% від
  звичайної ціни вхідних токенів (економія 60-90% на реальних
  навантаженнях). Рамка відео перебільшена: деградація якості (context
  rot) реальна незалежно від кешування, а твердження "платиш повну ціну за
  перечитування" - ні, якщо кеш працює.
- **"Context rot"** - підтверджено, формалізоване дослідження Chroma
  (2025) на 18 топових моделях показало реальне падіння точності на
  30-50% задовго до ліміту контекстного вікна.
- **Партнерство Anthropic + SpaceX, Colossus 1 в Мемфісі, подвоєння
  лімітів 6 травня 2026** - підтверджено, реальна угода (Anthropic платить
  xAI $1.25 млрд/міс за потужності колишнього дата-центру Grok), ліміти
  Pro/Max/Team/Enterprise реально подвоєні, обмеження по пікових годинах
  реально прибрані.
- **`/btw` команда** - підтверджено, реальна функція Claude Code.
- **Плагін Superpowers** - підтверджено, реальний плагін з воркфлоу
  brainstorm → plan → TDD → review.
- **Моделі Opus 4.7 / Sonnet 4.6 / Haiku 4.5** - застаріло вже на момент
  перегляду: відео знято у травні 2026, з тих пір вийшли Sonnet 5
  (30.06.2026) і Opus 5 (24.07.2026), актуальний дефолт зараз інший. Сама
  логіка поради (легка модель для легких задач) лишається вірною.
- **Субагенти "економлять токени"** - неповно: тримають чистим видимий
  чат, але за сумою можуть спалювати до ~7 разів більше токенів, ніж
  однопотокова робота. Спосіб боротьби із захламленням контексту, а не з
  витратою токенів як такою.

## Актуальність

Технічно добротне відео, майже без помилок, але назви моделей встигли
застаріти за ~3 місяці. Дата перевірки: 2026-08-02.

## Зв'язок з навчанням

Пряме перетинання зі StudyMate (capstone) і ДЗ7/8 (embeddings/пошук):
питання "як не давати історії діалогу розростатись і деградувати" - той
самий архітектурний вибір, що стоїть і перед StudyMate. Корисна паралель
для майбутнього курсу «Генеративний та агентний ШІ».

## Зв'язок з ERC

Пряме застосування без натяжок, бо Claude Code вже щодня використовується
на CharSet Inspector і в цьому репозиторії: `CLAUDE.md` до 200 рядків з
посиланнями підтверджує вже обраний підхід; Plan Mode перед великими
правками в CharSet Inspector; новий чат під кожну велику задачу; Routines
для розтягування 5-годинного ліміту при інтенсивній роботі.

## Практичний чек-лист

1. Новий чат - по завершенню задачі або при явних ознаках деградації, не
   за календарем. Проміжний варіант - `/rewind` → "Summarize from here"
   замість повного старту з нуля.
2. Дрібні правки - редагувати/відкочувати точково (GUI: олівець, CLI:
   `/rewind` → Restore conversation/code), повний відкат лише коли
   результат справді мимо.
3. Не писати "ні, я не те мав на увазі" другим повідомленням - правити
   перше.
4. Plan Mode - для нетривіальних задач, не для дрібниць.
5. `CLAUDE.md`/`AGENTS.md` - до ~200 рядків, деталі виносити в окремі md
   з посиланням.
6. Субагенти - для чистоти чату, а не заради економії токенів загалом.
7. Вимикати невикористовувані MCP на сесію, якщо не потрібні.

## Висновок

Відео варте застосування як практичний посібник: майже всі поради
підтверджені і додають реальну економію часу/токенів при інтенсивному
використанні Claude Code. Головне застереження: економія від коротких
чатів і `/btw` реальна через prompt caching трохи менше, ніж подає автор
(не "повна переплата за історію", а часткова), але сама рекомендація не
тримати чат на 100+ повідомлень лишається вірною - через context rot, а не
тільки через ціну.
